## Structured output

Each PHP file maps to a Python module beneath converted/, with sanitized Python identifiers and package __init__.py files. For example lib/math.php maps to converted/lib/math.py. A module/file name collision is rejected rather than silently overwriting source. Translation follows resolved file dependencies where acyclic. Cycles are reported and require review.

Translation requests are grouped at PHP top-level statement boundaries near 4,500 source characters. A truncated response gets one compact retry. A single large class or statement can still exceed a model's response budget and fail explicitly; this is not an arbitrary-project guarantee.

The report records file_map, translation_order, cycles, source-to-module symbol mapping, missing symbols, resolved literal includes and expected cross-module imports. STATIC_CHECKS_PASSED means these static checks passed, not that software architecture or all behavior is proven equivalent. External/dynamic calls remain explicitly outside static resolution. Graph checks don't reconstruct application routes, infrastructure, databases or deployment topology.

The ZIP includes converted/, registry.json, app.py, source/, requirements.txt, report.json and characterization tests. There is no flattened migrated.py. GET /health in the generated project lists module-qualified callable keys; POST /functions/{key} accepts {"args": [...]}. Check the generated project's /docs. Each file is behavior-tested separately using the existing Docker harness and up to two repairs, writing repairs back to its own module. Callbacks, namespaces, framework bootstrap, classes and side effects remain limitations. Only standalone functions with observed successful PHP outputs can receive EQUIVALENT.

The studio Output tab has a module selector. Graph shows symbol/dependency checks and the plan. The agents panel shows timestamped execution evidence. Completion does not override UNTESTED, MISMATCH or ERROR results.

## Accounts, authorization and history

SQLite data/accounts.sqlite3 stores:
- users(id, email, salt, password): normalized unique email and salted PBKDF2-HMAC-SHA256 password hash (600,000 iterations).
- sessions(token, user_id, csrf, expires): SHA256 digest of a random session token, CSRF value and expiry; seven-day sessions.
- jobs(id, user_id, created, label): job ownership and history metadata.
- attempts(client, at): basic 30-attempt-per-15-minute sign-in/signup IP throttling.

Session cookies are HttpOnly, SameSite=Strict, and Secure when served over HTTPS. Mutation requests require the signed-in session's X-CSRF-Token header. Cross-origin login/signup requests are rejected. Logout revokes the server session. The account database and job files are ignored by Git; back up both together if retaining user history. Password reset, email verification, admin controls and production identity integration are not included.

GET /api/jobs lists the current user's latest 100 jobs. Loading a previous job restores its report URL and permits a download if completed. Every status, report and download request checks ownership and returns 404 for another user's job. Other data/model APIs now require login as well. /api/health and static UI remain public. Jobs created through the web are assigned an owner before being enqueued.

Existing anonymous jobs are preserved on disk but are NOT automatically assigned to whichever person signs up first. They are inaccessible through the authenticated API unless an explicit ownership migration is performed later. CLI smoke jobs similarly have no web owner. In-flight worker jobs still do not automatically resume after a process restart; history storage survives, but durable queue/recovery remains future work. Run one backend process for this local prototype.

### Session endpoints

POST /api/auth/signup and /api/auth/login accept {"email":"...","password":"..."}; responses establish the cookie and return id, email, csrf. GET /api/auth/me restores the session and CSRF token after a refresh. POST /api/auth/logout requires X-CSRF-Token. The browser handles these automatically. Swagger now describes the job JSON body; direct API clients must also keep the session cookie and send the CSRF header on writes.

### Input-validation follow-up

Plain text without a PHP opening tag, invalid PHP syntax and tag/comment-only input are now rejected with HTTP 400 before job creation or any model call. Mixed HTML/PHP and <?= echo syntax remain accepted. Groq HTTP 403 errors are explicitly identified as model-service access/network errors, not PHP format errors. Invalid submissions rejected before job creation do not create history entries; previously created failed jobs remain in history. Regression coverage is in backend/test_workflow.py.

### Generated-Python validation (2026-11-22)

Translation units now remove complete Python Markdown wrappers and compile without executing code. Invalid Python receives up to two syntax-correction attempts. Exhaustion reports the PHP source file and generated Python line, and retains the rejected model output under report.translation_error for the owner to inspect. The Output tab exposes those diagnostics. Syntax corrections are separate from Docker behavior repair and do not prove equivalence. Fifteen backend checks passed; the calculator repo has not been verified end to end.

### Request budgets and completed-file reuse (2026-11-22)

Requests now carry only current-file symbols/dependencies plus the module map. Output reservations are estimated against an 8,000-token request budget, and HTTP 413 feedback reduces the next reservation rather than retrying an identical oversized request. The estimate is not an exact tokenizer or a complete rolling TPM scheduler; provider 429 handling still uses the shared retry/backoff helper. A source unit that cannot fit even a small output reservation fails clearly instead of consuming repeated identical requests.

Each translated file is checkpointed. A new job by the same owner can reuse syntax-valid modules from the latest 100 owned jobs only when the entire source snapshot and module map are identical. This does not resume an old job automatically or share another user's cache. Reuse is recorded in translation_files and agent events. Reused code is still checked and behavior-tested where supported. Changed repository commits may change archive paths and therefore correctly prevent reuse. Original generation tokens remain in the earlier job; reused modules have zero generation tokens in the new job.
